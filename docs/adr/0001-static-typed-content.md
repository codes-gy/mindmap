# 콘텐츠는 저장소의 TypeScript 모듈로 두고 모든 페이지를 빌드 때 만든다

v1은 빌드 과정 없는 정적 사이트였다. 개념마다 주소를 주고, 검색하고, 검색 엔진에 노출하려고 Next.js로 옮겼다(PR #1). 이때 CMS나 데이터베이스를 두지 않았다. 콘텐츠는 `content/<탭>/<탭>-<n>.ts`의 타입 있는 데이터로 저장소에 두고, 개념 페이지와 설명 카드, 전체 노트는 `generateStaticParams`로 빌드 때 모두 만든다. 탭 5개, 주제 41개, 개념 858개에서 정적 페이지 1,800여 개가 나온다. 혼자 쓰는 학습 페이지라 편집 화면이 없어도 되고, 대신 서버 없이 빠르게 뜨며 타입 검사와 리뷰를 그대로 쓸 수 있다.

## Consequences

- 콘텐츠를 고치려면 커밋하고 다시 배포해야 한다.
- 타입이 잡지 못하는 오류는 `npm run validate`가 `prebuild`에서 막는다. 잡는 것은 id와 제목 중복, 없는 관련 개념, 비교 표 칸 수 같은 것이다. 깨진 데이터는 빌드가 실패해 배포되지 않는다.
- 검색도 서버 없이 한다. 빌드 전에 `public/search-index.json`을 만들고, 브라우저가 이 파일을 받아 검색한다.
